# core/engine/ — voices, sample packs and the audio graph

The sounds the band engine plays through: the synth voices (`synth-*.ts`), the sample-pack
voices (`sample-voice.ts`, `pack-runtime.ts`, `instrument-registry.ts`), the bus graph and reverb
(`engine.ts` `initAudio()`, `reverb.ts`). The old chord parser (`chords-engine.ts`) is gone with
the v1 text-chart format (#1740). The old worker-based generators that used to live here were deleted with the
old engine (#1404); the band's musical rules are in `band/CLAUDE.md` and
`docs/design/band-engine.md`. The rule numbers below are kept from the old file, so a reference to
one elsewhere still points at the same rule.

## Drums

17. **Two independent drum playback paths converge on one shared bus.** Synth voices (`synth-drums.ts`) and sample packs (`sample-voice.ts` `playSampledStrike`, native-rate, no per-voice filtering) both feed the same `drumsHP → drumsMud → drumsAir` chain in `engine.ts` `initAudio()`. Bus-level EQ is the only universal tone lever; a per-voice synth tweak (tom decay, kick envelope) never reaches an installed sample pack. The one per-hit treatment on the sampled path is the ghost snare (`ghostSnareChain`, #1998): with no soft snare take in the kit, the band's ghost stroke (`Ghost`, its `ghost` piece) strikes the snare take through a low-pass and a short decay. The sampled path also owns its share of the kick's sidechain duck (`duckKickSidechain`), so a new seam that plays the kick must call it too.

## Synth / sample / mix

18. **`killActiveVoices` (`synth-utils.ts`) never actually reaches zero gain before hard-stopping the node** — it fades via `setTargetAtTime` (exponential, asymptotic) then stops oscillators/buffer-sources at `time + fadeTime + 0.05`, when gain is still ~3%. Audible click on any rapid voice-steal, worst on noise sources. The deleted harmony voice (#1436) fixed it locally with a linear ramp to true 0 and a deferred stop; the soloist still uses the clicky shared helper — first suspect if a rebuilt voice clicks on cutoff.
19. **A dead synth branch is invisible to the by-ear listening gate.** Before presenting any synth-voice story for audition, grep the engine's actual note emission (`note.style = …`) against the branch's trigger key — a branch keyed on a value the engine never emits passes the gate silently (owner hears the fallback voice and approves, mistaking absence for presence). Reviving a dead branch also means its DSP constants were never ear-checked — audit them as newly-written, not as trusted existing code.
20. **Read `engine.ts` `initAudio()` first for any audio-graph question.** The bus architecture — reverb sends, per-module EQ chains, master limiter/sidechain — lives there, not scattered in the `synth-*.ts` voice files.
21. Web Audio footguns worth re-checking on any DSP change: `0 * NaN === NaN` (no short-circuit — guard interpolation where one operand might be `undefined`/`NaN`, e.g. `bandIntensity` in tests); float subtraction isn't exact for envelope-time interpolation (use lerp form `a*(1-t) + b*t`, not `start - t*delta`); `BiquadFilterNode.Q` is in **decibels** for `lowpass`/`highpass` (`Q=0dB` is already a ~1.17× peak; need `Q ≤ -3dB` for a non-resonant filter, and a resonant one inside a feedback loop pushes loop gain over 1); `AudioScheduledSourceNode.stop()` before `start()` throws `InvalidStateError` — always call every `start()` in a voice builder before scheduling any `stop()`, and wrap per-voice builders in try/catch so one note's throw can't abort a whole chord's `forEach`.
22. **No cross-coupled `DelayNode` feedback networks.** Chromium's Web Audio self-oscillates on a matrix-mixed FDN regardless of provably sub-unity loop gain on paper — `reverb.ts` is deliberately Freeverb/Schroeder topology (parallel single-loop combs → series allpass, no cross-coupling) because of this. Debug any feedback/stability issue with an `OfflineAudioContext` impulse-response bisection render (see `tests/browser/reverb-stability.browser.test.ts`, run by `npm run test:browser`), not by ear/deploy cycles — reasoning about FDN stability from the math was a dead end here for two days.
23. Normalize an additive partial bank (chord body, etc.) by target **RMS**, not peak-amplitude sum — peak-sum normalization under-delivers loudness by the bank's crest factor (~7dB for 9 uncorrelated partials), sounding fine on dense material but vanishing on exposed low-intensity notes.
24. **Sample-pack tuning:** an occasionally-sour note on a pack voice is almost always an integer-rounded zone `rootMidi` in the manifest — fix is a **fractional** `rootMidi` (the loader's `pitchRatio` math is float-clean, no re-encode needed). Diagnostic: scattered per-zone cents error = a real bug; a smooth monotonic ramp (e.g. piano stretch tuning) = intended physics, leave it.
25. **A thin/metallic ring on a sample-pack voice = register overshoot past the pack's top sampled zone**, upward-pitch-shifting a stretched sample into aliasing. `foldToSampledCeiling` (`sample-voice.ts`) folds an out-of-range note down whole octaves before `pickZone`; any new pack-playing seam (a future instrument lane) needs the same guard, or it'll click through undetected — it only fires on the rare top-register note.
26. `playSampledNote` clamps its envelope peak to `MAX_SAMPLE_PEAK` (currently 8) so a loudness-normalized pack can play above unity to match a synth voice's mix seat. A seam that itself does `Math.min(1, vol * gainForPack(...))` silently re-defeats that headroom — if a mix-calibration metric won't move when you raise a pack's gain, suspect a clamp somewhere in that seam before the tool.
27. **`scrambleHash` (`hash-utils.ts`) is the stateless, seed-tuple-indexed mulberry32 helper** the voices use for timbral humanising: dropping or adding a draw desyncs nothing else. Never a bare LCG on small integer seeds (sawtooths); see `docs/guides/musical-engine-patterns.md` for the base determinism pattern.
28. **A sampled voice is only stopped if it names its lane.** `playSampledNote` and `playSampledStrike` take `lane` (`chords`/`bass`/`soloist`/`drums`) and register the voice per audio context; each lane's kill function (`killAllPianoNotes`, `killBassNote`, `killSoloistNote`, `killDrumNote`) calls `releaseLaneVoices` (`lane-voices.ts`, the one registry) for it. A new pack-playing seam that leaves `lane` out plays on after Stop for its whole written length (#1530: a held organ chord rang for bars). `tests/unit/engine/stop-silences-sampled-lanes.test.ts` holds each seam to it. **The synth chord voice registers there too** (`synth-chords.ts`, `trackLaneVoice`, #1569): a no-pedal chord — every band chord — was once registered nowhere (the sustain pedal and its `heldNotes` set are gone) and rang to its written end after Stop (measured live, 3 of 6 runs on a whole-note ballad). A voice scheduled ahead of the clock is stopped at its own start, never faded from it (the fade would start from the default gain of 1: a click). `tests/unit/engine/stop-silences-synth-chords.test.ts`; `npm run live:capture` on a held-chord scene is the live check. **Every synth voice is cut before it sounds** (#1999): the host sends a note up to 150 ms ahead, so a synth bass note, drum hit, lead note or chord onset transient registers its outputs with `cancelAheadOnStop` as it is made, and a Stop before its start disconnects them (`tests/unit/engine/stop-cancels-notes-ahead.test.ts`). A new synth voice must do the same, or it sounds once after Stop. A sustained synth voice that a newer note can be sent ahead of registers its sounding fade with `trackLaneVoice` as well (the synth bass): a "latest note" field such as `lastBassGain` points at the note sent ahead, not the one sounding. A sampled strike sent ahead is pinned to 0 and stopped at its start, never choked from it.
29. **A sustaining pack loops by crossfade, not loop points.** A pack marked `sustains` in the catalog (the organ) plays a note longer than its recording by starting the recording again past its attack, each pass crossfaded into the next at equal power (`playSampledNote`'s `sustain`, #1532). The organ's tonewheels are not phase-locked, so no loop point joins cleanly; don't swap this for `source.loop`. A note its recording covers takes the old single-source path, sample for sample. A struck or plucked pack must not be marked: its note should die with its recording. `tests/browser/organ-sustain.browser.test.ts` renders the loop in a real context.
30. **The master ends in a look-ahead true-peak limiter, an `AudioWorklet` (#2002)**: `gain → glue → makeup → limiter → volume → destination`. `master-limiter.ts` loads `master-limiter.worklet.js` (plain JS, the same file in Chromium, WebKit and node renders) and wires it in asynchronously, so the master is silent until `masterChainReady(ctx)` resolves: anything new that sounds — a live path or an offline render — awaits it first (the runtime's `readyToPlay` and audition, `renderBandPasses`). A browser where the module fails or stalls (3 s) gets the old `DynamicsCompressorNode` brick wall as a safety limiter instead, never silence and never the up-to-+12.4 dB make-up straight into the destination. The master volume is a plain level after the limiter (1 = the calibrated loudness; an audio export always renders at 1, `renderBandPasses`), and `MASTER_MAKEUP_DB` (`core/config.ts`) brings each style to −16 LUFS, restored on every `restoreGains` (a chart opens with the runtime's subscriber off, so no genre effect runs) and glided on `SET_GENRE_FEEL`: a change to a voice's or pack's level, a bus or the glue moves a style's loudness, so re-measure with `scripts/scenes/loudness-styles.json` (`docs/guides/listening-gate-tools.md`). Don't put a `DynamicsCompressorNode` back as the limiter: it detects sample peaks only, adds its own make-up gain and differs between engines.
