# public/engine/grooves/ — per-genre drum strategy files

13 genre-specific drum strategy modules (`rock.ts` … `metal.ts`) dispatched by `getStrategy()` in `../groove-engine.ts`, plus `utils.ts` (the shared contract: `GrooveContext`, `DrumStepBase`, `DEFAULT_CONFIG`, `binaryTier`/`makeMotifSelector`, `applyStandardBase`, `placementSkew`, `scaleVelocity`, `isBackbeatAdjacentStep`). Every file here exports `config`, `getMotif`, and `applyOverrides(context, state): DrumStepBase` — a new genre file must implement all three to be reachable from dispatch.

**`getMotif` is built via `makeMotifSelector` in every genre except one sanctioned hand-roll: `disco.ts`.** Disco hand-rolls it specifically to bypass the factory's `intensityFloor` guard (default `INTENSITY_BANDS.LOW`), which would force motif 0 below intensity 0.35 — #997 deliberately made disco's busy/foundation choice intensity-INVARIANT (seed drives density; intensity only scales velocity). Any *new* genre file should use `makeMotifSelector`; hand-rolling needs the same kind of documented musical reason, stated at the function.

## Canonical-key routing (read `../../../CLAUDE.md` § Naming/Canonicalization first)

- **The `strategies` map in `groove-engine.ts` is keyed by `groove.genreFeel`'s canonical *feel* string, which is NOT always the genre's display name or drum-preset name.** Two of the 13 keys diverge on purpose: Ska-Punk's feel is `'Ska'` (keyed `Ska: skaPunk`, not `'Ska-Punk'`) and Bossa's feel is `'Bossa Nova'` (keyed `'Bossa Nova': latin`, not `'Bossa'` or `'Latin'`). `getStrategy()` also has an explicit `isLatinStyle` pre-check (`genreFeel === 'Bossa Nova' || lastSmartGenre === 'Bossa'`) ahead of the table lookup — don't assume the table alone is the full dispatch path for Bossa.
- **`latin.ts` is NOT dead/phantom code** — it is the live, sole engine for Bossa (the one selectable Latin-family genre), including the compound-meter Bembé bell when Bossa is set to 6/8 or 12/8 (#628). The generic `'Latin'` feel and the World/Latin drum-preset bank (Salsa, Afro-Cuban 6/8, Samba, Afrobeat) were deliberately retired as unreachable — don't resurrect them as a "fix" without a fresh, fully-wired genre-picker story; `latin.ts` staying wired to Bossa is intentional, not a leftover.
- **`tests/standards/genre-feel-canon-guard.test.ts` (#1130, extended #1208) guards the `strategies` table plus ten genre-subset collections** — `BASS_SPACE_FEELS`, `HAT_SPINE_GENRES`, `STICKY_GENRES`, `SUSTAINED_COMP_GENRES`, `RING_THROUGH_GENRES`, `HALL_GENRES`, `GENRE_INTENSITY_FLOORS`, `SUBTRACTION_PILOT_GENRES`, `HARMONY_GENRE_PROFILES`, `DROP_FRIENDLY_GENRES`. **Adding a new genre-keyed table? `export` it and register it in that file's `FEEL_SUBSETS` map in the same pass** — that registration is the whole defense, because a dead genre key never throws; the genre just silently doesn't get the behavior (which is how #1169's hip-hop drop gate stayed broken from May to July). Also grep `smart-genres.ts` for the canonical `feel:` value rather than inventing a spelling. Note the guard is **validity-only**: it proves every member *can* match a real feel, not that the membership is musically right — only `DROP_FRIENDLY_GENRES` has a hard-coded membership pin making idiom edits deliberate.
- **A single wrong genre key rarely lives in one place — it clusters across map shapes.** When hunting for or fixing a dead genre key, grep the whole repo for the bad string in ALL of: `Record<...>` object keys, `Set(...).has(...)` membership, substring `arr.some(name => g.includes(name))` checks (note the *inverted* trap: a longer needle like `'ska-punk'` against a shorter haystack value like `'ska'` never matches — `'ska'.includes('ska-punk')` is `false`), and direct `=== 'X'` equality branches. A `Record<`-only grep misses the other three shapes.
- **Fix the test fixtures in the same pass as any canonical-key fix.** A critique test that injects the WRONG (matching-the-bug) key as its fixture will pass while validating a path production never takes — see `../../../CLAUDE.md`-adjacent test-harness-divergence pattern. Prefer an integration-shaped fixture that dispatches genre state and lets the engine resolve the key itself, not one that hands the strategy the canonical key directly (that bypasses any upstream override that might silently rewrite it, e.g. `accompaniment.ts`'s `chords.style === 'jazz'` collapse, which historically ate Bossa/Blues genre identity before a carve-out fixed it).

## Meter and section-seed gotchas for tests

Full test-fixture detail (the 3-knob `sectionSeed`/intensity-tier/`loopMotifCeiling` recipe, the `arranger.timeSignature` mock requirement) lives in `tests/CLAUDE.md` — don't duplicate it here. The mechanism itself (bar-stable intensity vs. live `bandIntensity`, the `noLiveConductor` latch) is `../CLAUDE.md` #16 — don't reintroduce a direct `getMotif(..., bandIntensity)` call in a groove file, that's the mid-bar pattern-flip stutter bug (#841). This directory's own wrinkle, not covered by either: **`applyGrooveOverrides` (`groove-engine.ts`) recomputes `stepsPerBar`/`loopStep` itself from `arranger.timeSignature`**, defaulting to `'4/4'` when the slice is absent — any `params.stepsPerBar` a caller passes is silently ignored, not read.

## Swing / feel

- **`calculateStepDuration` (`groove-engine.ts`) is the single swing authority for every lane — don't add a per-groove-file swing implementation.** The `sub` field (`'8th'` vs `'16th'`) is the load-bearing feel distinction, not the swing ratio: two genres at the same numeric `swing` value on different `sub` grids sound completely different (8th-swing = shuffle/lilt feel, 16th-swing = laid-back Dilla/funk pocket). If you touch a genre's swing, assert the grid too — `tests/standards/swing-ratio-audit.test.ts` is the oracle; re-run it before changing any genre's `swing`/`sub` in `smart-genres.ts`.
- Per-genre timing LEAN (ahead-of/behind-the-beat, as opposed to swing) lives entirely in `GENRE_POCKET`/`getBandPocket` in `../coordination-engine.ts`, not in this directory — grooves/ files have no pocket logic to edit.

## Overrides: replace vs. additive

- **A per-step override that sets `shouldPlay = true` with a new `soundName`/`velocity` REPLACES the strategy's hit outright — it does not layer on top.** That's correct for sample swaps (e.g. Open → Crash) but wrong for a decorative ornament that should sit under an existing hit. Before adding a genre-specific flourish gated to fire on backbeat-adjacent quarter-note positions, check `isBackbeatAdjacentStep()` (`utils.ts`) and ask whether it could silently steal beats 2/4 of the final bar — the loudest snare hits in the form — by overwriting them with a quieter ornament sound. The engine has no multi-sample lane today, so genuine additive layering requires firing the ornament on a *different* instrument lane (e.g. a Sidestick lane), not the Snare lane the strategy already claimed.
