# public/engine/ — generative engine core

The worker-thread musical engines: soloist, coordination/drums, synth/sample/mix, and chords/comping/harmony. Read `CLAUDE.md` § Musical Logic & Generative Standards first — this file goes deeper, not wider. Genre-strategy specifics (per-genre pocket/swing/override mechanics) live one level down in `grooves/CLAUDE.md`; worker-sync plumbing (main↔worker state mirroring) lives in `public/CLAUDE.md`.

## Soloist (Dynamic Head / SRDC)

1. **Single engine, no legacy fallback.** `getSoloistNotePhraseFirst` (`soloist-phrase-first.ts`) is the only soloist engine — `soloist.ts`, `soloist-rhythm-engine.ts`, and the old weighted picker `selectPitchAndDevices` are all deleted. `soloist-pitch-engine.ts` today is just `chordTargetTones`/`classifyChordQuality` (~130 lines), not a picker.
2. **There is no live weighted pitch picker — don't port the `weight *=` pattern here.** `landOnTarget` is a **deterministic** snap-to-guide-tone at strong beats; no lottery. The SRDC arc and rhythm-placement knobs (`syncopationLikelihood` and friends in `STYLE_CONFIG`) are baked at **seed time** in `soloist-seeder.ts` (`isDepartureCategory`, `seedDepartureLift`), not read by any live per-tick weighting — `soloist-rhythm-engine.ts` (the old live consumer) no longer exists. A "make genre X more offbeat/departure-heavy" story is a seed-time knob change, not a final-stage multiplier.
3. **Seed `loopLengthSteps` ≠ one arrangement lap.** `generateSessionSeed` unrolls up to a 128-bar development span, so `loopLengthSteps` for a 12-bar blues is ~11× `arranger.totalSteps`. The arrangement itself loops every `arranger.totalSteps` (`scheduler-core.ts` increments `currentLoopCount` there). Measure "loop 0" density/gaps by bucketing on `arranger.totalSteps` + `currentLoopCount`, never on `loopLengthSteps` — the wrong frame fabricates false gaps out of composed rests that only play many loops later.
4. **Hook cell (`hookRole`, measure-0 arpeggio) is chord-TONE, re-rooted per block, folded as ONE shared octave offset.** Per-note octave folding or per-chord-scale mapping both destroy the recurring shape (verified dead three times before this design). Live: `isHook` must skip `diatonicTranspose` key-snap AND the strong-beat `landOnTarget` snap (a verbatim branch ahead of `isStrongBeat`) or the pinned shape gets re-scrambled.
5. **Motif inheritance (`UNROLLED_INHERIT_OPS`) only fires when `isUnrolledForm`** (short/looping charts `unrollArrangement` synthesizes a macro-form for) — a long multi-section chart shows zero inheritance by design, don't read that as broken. Jazz collapses verse+solo into one `'jazz'` category, so the Solo section takes the ordinary restatement path, not the inheritance branch — it needs its own tail-guard (`eligible = n => n.beatOffset >= tsConfig.beats`) so measure 0 (the hook) stays verbatim there too.
6. **`currentChord.intervals` (read via `getChordAtStep`) is the COMPER's voicing, not functional chord tones.** For `BASS_SPACE_FEELS` genres (`voicing-policy.ts`) with the bass lane active, 7th/min7/maj7 voicings are rootless and can include tensions — so the soloist's `chordMask` treats the root as a non-chord-tone. Any feature needing true functional targets (bend/slide harmonic resolution) must derive from `quality` via `classifyChordQuality`/`FUNCTIONAL_PILLARS_BY_QUALITY`, not read the mask directly.
7. **A pitch-bend gesture renders on independent paths that can silently diverge:** synth (`synth-soloist.ts`), sampled (`sample-voice.ts` `scheduleSampleBend`), `.mid` export (`midi-worker-logic.ts` `emitBendGesture` — a separate waypoint polyline), and the scalar `bendStartInterval` entry-scoop at THREE more sites (`midi-worker-logic.ts` note + resolution emission, `midi-scheduler.ts` live MIDI-out). Changing a gesture's shape needs all of them checked and a `.mid`-export assertion added — the export path has no shared code with the audio voices. Convention: **positive pitch-wheel = UP**, everywhere.
8. **Expression devices are mutually-exclusive-gated by negative guards on each other** (`vibrato` computed first; `cry` requires `!vibrato && !inFlurry && bendStartInterval===0`; grace-slide requires `!isApexStep && !inFlurry && bendStartInterval===0`). Raising one device's fire-rate can silently steal notes from another instead of adding new expression — grep the downstream `!<device>` guards before loosening any rate. Hard ceiling: the §10 expr-rate critique caps total expression <30%, tightest in Country (stacks slide+scoop+vibrato).
9. **`diatonicNeighbor`, not `diatonicShift(±1)`, for a true step-wise approach into a possibly-chromatic target** (e.g. a dominant ♭7). `diatonicShift` snaps to the at-or-below scale degree *then* steps a further degree — for a chromatic source that skips the actual neighbor and leaps a third. Smell: any approach/enclosure/leading-tone code calling a `shift(x, -1)` built for transposition.
10. **Song-ending tonic is inferred from the cadence** (`inferResolutionTonic` in `resolution.ts`), not read blindly off `arranger.key` — a relative-minor chart (e.g. notated major but cadencing `ii°–V–vi`) must land on the true tonic. Dominant-quality approach detection tests the `quality` STRING (`{7,9,11,13,7alt,...}` + aug/aug7), never `getIntervals` (voicing-spread is unreliable for this).

## Coordination & worker-internal state

11. **`CoordinationContext` is worker-INTERNAL and never crosses to the main thread** — built fresh per tick by `createCoordinationContext()`, not a `deepSignal` slice, absent from `getSyncState()`/`syncWorker()`/`WORKER_MSG.*`. A new `coordination.*` field needs no main-thread mirror; grep `getSyncState()` before assuming a worker-contract review applies.
12. **Sticky-across-tick state goes in `CoordinationCarryover`, owned by exactly three production hosts that must each init/reset it independently:** `workerContext` (`public/engine/worker-orchestrator.ts`, via `resetCoordinationCarryover`) for live playback, `ExportProcessor` (`public/engine/midi-worker-logic.ts`) for MIDI export, and `renderClonedStateToWav` (`public/export/audio-export.ts`) for detached WAV renders. The analysis paths in `scripts/ensemble-analysis-utils.ts` and `scripts/mix-report.ts` mirror that contract so their evidence matches production. Add a new sticky field to every host in the same commit, or one path silently runs on `undefined`. Always age-cap sticky values so a single-shot event doesn't permanently steer downstream behavior.
13. Every coordination-context field carries `// writer:`/`// readable-after:` comments in `createCoordinationContext()`, guarded by `tests/unit/engine/producer-order.test.ts` (mocks a producer to a sentinel, spies on a consumer). Reordering producers without updating both is exactly what this test exists to catch.

## Drums

14. **The motif INDEX, not the entropy phase, is the audible per-loop Chorus Evolution lever.** `entropyMultiplier` measures ~0 audible effect (genres' own strategy ghost rolls dominate hit count at any intensity); `loopMotifCeiling(currentLoopCount)` clamping the genre's `getMotif(...)` call is what actually varies the pattern loop-to-loop. A "busier" motif index often sounds *sparser*, not denser (a different, more spread pattern) — guard for divergence across loops, never a monotonic hit-count increase.
15. **`drumComplexity` wears two hats:** it's a coarse on/off gate into `getMotif` (`<0.3` → motif 0, not a fine density knob there) AND a direct density input to jazz/blues/latin ghost/comp probabilities (a real knob there). Don't assume tuning it moves both the same way.
16. **Motif index must be selected from BAR-STABLE intensity, never live ramping `bandIntensity`** — a conductor ramp crossing a motif tier boundary mid-bar flips the skeleton mid-phrase (stutter). Live audio path reconstructs the bar-downbeat intensity from the conductor ramp (`motifSelectionIntensity` in `section-overrides.ts`, inverting the shared `RAMP_INTENSITY_MULTIPLIER`); worker/export paths can't reconstruct, so they latch `bandIntensity` into `playback.motifBarIntensity` at each bar downbeat when `noLiveConductor` is set, and that value reads as authoritative. **Gate on the explicit `noLiveConductor` flag, never on `!state.conductor` truthiness** — the worker/export paths always carry a present-but-never-synced default `conductor` slice, so `!state.conductor` is never true there and a gate keyed on it is dead code that silently falls through to stale reconstruction.
17. **Two independent drum playback paths converge on one shared bus.** Synth voices (`synth-drums.ts`) and sample packs (`sample-voice.ts` `playSampledStrike`, native-rate, no per-voice filtering) both feed the same `drumsHP → drumsMud → drumsAir` chain in `engine.ts` `initAudio()`. Bus-level EQ is the only universal tone lever; a per-voice synth tweak (tom decay, kick envelope) never reaches an installed sample pack.

## Synth / sample / mix

18. **`killActiveVoices` (`synth-utils.ts`) never actually reaches zero gain before hard-stopping the node** — it fades via `setTargetAtTime` (exponential, asymptotic) then stops oscillators/buffer-sources at `time + fadeTime + 0.05`, when gain is still ~3%. Audible click on any rapid voice-steal, worst on noise sources. Harmony has a local fix (`killHarmonyVoice`, linear ramp to true 0, deferred stop); bass/soloist/drums still share the clicky shared helper — first suspect if a rebuilt voice clicks on cutoff.
19. **A dead synth branch is invisible to the by-ear listening gate.** Before presenting any synth-voice story for audition, grep the engine's actual note emission (`note.style = …`) against the branch's trigger key — a branch keyed on a value the engine never emits passes the gate silently (owner hears the fallback voice and approves, mistaking absence for presence). Reviving a dead branch also means its DSP constants were never ear-checked — audit them as newly-written, not as trusted existing code.
20. **Read `engine.ts` `initAudio()` first for any audio-graph question.** The bus architecture — reverb sends, per-module EQ chains, master limiter/sidechain — lives there, not scattered in the `synth-*.ts` voice files.
21. Web Audio footguns worth re-checking on any DSP change: `0 * NaN === NaN` (no short-circuit — guard interpolation where one operand might be `undefined`/`NaN`, e.g. `bandIntensity` in tests); float subtraction isn't exact for envelope-time interpolation (use lerp form `a*(1-t) + b*t`, not `start - t*delta`); `BiquadFilterNode.Q` is in **decibels** for `lowpass`/`highpass` (`Q=0dB` is already a ~1.17× peak; need `Q ≤ -3dB` for a non-resonant filter, and a resonant one inside a feedback loop pushes loop gain over 1); `AudioScheduledSourceNode.stop()` before `start()` throws `InvalidStateError` — always call every `start()` in a voice builder before scheduling any `stop()`, and wrap per-voice builders in try/catch so one note's throw can't abort a whole chord's `forEach`.
22. **No cross-coupled `DelayNode` feedback networks.** Chromium's Web Audio self-oscillates on a matrix-mixed FDN regardless of provably sub-unity loop gain on paper — `reverb.ts` is deliberately Freeverb/Schroeder topology (parallel single-loop combs → series allpass, no cross-coupling) because of this. Debug any feedback/stability issue with an `OfflineAudioContext` impulse-response bisection render (see `tests/browser/reverb-stability.browser.test.ts`, run by `npm run test:browser`), not by ear/deploy cycles — reasoning about FDN stability from the math was a dead end here for two days.
23. Normalize an additive partial bank (chord body, etc.) by target **RMS**, not peak-amplitude sum — peak-sum normalization under-delivers loudness by the bank's crest factor (~7dB for 9 uncorrelated partials), sounding fine on dense material but vanishing on exposed low-intensity notes.
24. **Sample-pack tuning:** an occasionally-sour note on a pack voice is almost always an integer-rounded zone `rootMidi` in the manifest — fix is a **fractional** `rootMidi` (the loader's `pitchRatio` math is float-clean, no re-encode needed). Diagnostic: scattered per-zone cents error = a real bug; a smooth monotonic ramp (e.g. piano stretch tuning) = intended physics, leave it.
25. **A thin/metallic ring on a sample-pack voice = register overshoot past the pack's top sampled zone**, upward-pitch-shifting a stretched sample into aliasing. `foldToSampledCeiling` (`sample-voice.ts`) folds an out-of-range note down whole octaves before `pickZone`; any new pack-playing seam (a future instrument lane) needs the same guard, or it'll click through undetected — it only fires on the rare top-register note.
26. `playSampledNote` clamps its envelope peak to `MAX_SAMPLE_PEAK` (currently 8) so a loudness-normalized pack can play above unity to match a synth voice's mix seat. A seam that itself does `Math.min(1, vol * gainForPack(...))` silently re-defeats that headroom — if a mix-calibration metric won't move when you raise a pack's gain, suspect a clamp somewhere in that seam before the tool.
27. **Two PRNG idioms coexist, and only one has a stream-order hazard.** `createPRNG` (`hash-utils.ts`, moved out of `public/utils.ts` in #1179) is a stateful, sequential mulberry32 generator used for seed-time generation (e.g. `soloist-seeder.ts`) — changing how many draws a code path consumes desyncs every downstream consumer sharing that stream, so a metric regression right after a device/selection change should be attributed to stream-shift *before* being treated as a real behavioral regression (bisect the metric's actual mechanism, not just the changed line). `scrambleHash` (`hash-utils.ts`) is stateless and indexed by an explicit seed tuple (per-tick `compDraw`-style calls) — dropping or adding a draw there does NOT desync anything else. Never a bare LCG on small integer seeds (sawtooths); `scrambleHash` is the canonical mulberry32 helper — see `docs/guides/musical-engine-patterns.md` for the base determinism pattern. This file adds: after any `Math.random → scrambleHash` migration, audit every `< X` ceiling gate for reachability at the *dominant* seed's quantile — a ceiling that happens to sit below that quantile is permanently dead at that seed, and a test that mocks `Math.random` won't catch it (the new gate ignores that mock entirely).

## Chords, comping & harmony

28. **`getAccompanimentNotes` (`accompaniment.ts`) owns the live comp voicing and timing, not just the rhythm cell** — the cell alone comes from `generateCompingPattern`. Re-voicing a chord in place must land as a late override *before* the internal `rotateVoicingFreqs` step (or an early return building notes straight from freqs); editing mid-pipeline gets mangled by the register-slotting pass downstream.
29. `getBestInversion`'s baseline places each chord interval at its nearest octave independently and can cluster a minor 2nd; the cost-gated voice-leading pass only runs for `enableVoiceLeading` genres (Jazz/Bossa/Blues). De-cluster the baseline so VL has something sane to smooth — don't rely on VL to fix a bad baseline, since non-VL genres get the bad baseline unfixed.
30. **A sparse/behind-the-beat comping genre needs explicit exemption from the downbeat-overlay backfill** in `comping-emit.ts`'s `emitCompNotes` (`PULSE_ANCHOR_GENRES`, plus genre-specific `genre !== '<Genre>'` checks on the force-the-One and group-start anchors). Without it, a rhythm cell that deliberately never hits step 0 still gets the downbeat thumped back in on ~80% of bars by the generic backfill — a cell-only critique test passes while the audible output re-adds the exact pulse the genre was designed to avoid.
31. Harmony (`getHarmonyNotes`/`finalizeHarmonyNotes`) computes `freq` **before** the register clamp; `tick-logic.ts` clamps the midi to ≤84 afterward. Any consumer reading harmony pitch post-clamp must recompute freq from the clamped midi, not reuse the pre-clamp value.
32. Voice-release scheduling (chords `activeChordVoices` handles, harmony `killHarmonyNote`) must release at the scheduled `time`, never `currentTime` — the scheduler runs ~200-400ms ahead of real time, so releasing "now" cuts a note early or late relative to what's actually sounding.

## Style/genre routing traps

33. **Before declaring a bass/chord/soloist style key dead, check every routing layer, not just the genre map.** Bass additionally routes via `SMART_BASS_STYLE_MAP`/`resolveMappedStyle` keyed off `lastDrumPreset` — a drum *preset* alone (independent of genre) can make a style reachable. Separately, persisted-session/share-URL hydration (`state-hydration.ts`) validates a saved style against the `BASS_STYLES`/`SOLOIST_STYLES` lists in `instrument-styles.ts`, independent of any picker — deleting the implementation but leaving the list entry means an old save passes validation, keeps the now-dead key, and the instrument goes **silently mute** instead of falling back to a default.
34. "No UI trigger path" is not evidence of dead code. Before deleting anything keyed by a musical name (a drum lane, a percussion voice, a style id), grep the three non-obvious runtime producers: `public/engine/grooves/*.ts` (genre engines writing lane arrays), `public/engine/fills.ts` (fill patterns referencing lane names), and `tests/standards/*-critique.test.ts` (critiques that exercise the production path). A UI affordance gap and a wiring gap are different claims with the same surface wording.

## Working on this engine

35. When an audit item names one site (a gate, predicate, or emission), grep the same file for the **paired site implementing the other half of the same musical gesture** — an activation gate and its own separately-hardcoded emission-side check are a recurring miss (e.g. a fill's activation window updated for a new time signature while its emission predicate keeps the old hardcoded offset). Consistently caught by review when skipped, so budget for the patch round if you skip the grep.
36. Raw `step` passed into engines is a **monotonic transport counter that never resets at a loop boundary**; `sectionMap` boundaries and `barIndex` are loop-relative (`0..totalSteps`). Any position compare or seed derived from `step` against a section/bar boundary must wrap it first — `((step % totalSteps) + totalSteps) % totalSteps` — or the feature only ever fires on the very first lap and goes silently inert every loop after, invisible to any test that doesn't run ≥2 loops in the loop-relative frame. If the value feeds a lookahead lambda (future absolute steps), wrap per-argument inside the lambda, not once outside it.
37. Prefer a formula that's correct for every input over a fail-loud throw in a shared hot-path pure function (e.g. `getStepInfo`) — grep tests and call sites for a legitimate exercise of the "impossible" edge case first; they often exist, and a per-step worker function shouldn't crash mid-playback over a static-config edge case anyway.
