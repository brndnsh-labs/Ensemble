# Epic 2: Form & Arrangement Awareness

## Why this epic exists

Form is implemented for two of six engines: soloist (SRDC, Imperfect Symmetry, Loop 0/1/2+ branching) and drums (per-section seed, fill triggering). The other four — bass, chords, harmony, accompaniment — are functionally form-blind. They WRITE section metadata onto chord objects but never READ it at generation time. CLAUDE.md's marquee Chorus Evolution claim, the Imperfect Symmetry pattern, and the conductor's `lyricalBias` arc all stop one engine short of reaching the listener.

This is the epic where the "the band sounds like a machine on repeat passes" reputation lives. Highest perceptual impact relative to surface-area touched.

## Stories

### S1. Drums: motif complexity cap relaxes per loop
`groove-engine.ts:129-135` consumed `orchestration.motifComplexity` at per-tick time but did not vary the cap with loop count. A misplaced static block in `drum-seeder.ts:154-159` had tried to fake this from seed-time `index` comparisons, but the seeder runs once and has no access to `playback.currentLoopCount`, so the cap was permanent for all loops. The fix: delete the seeder block and apply `Math.min(2, 1 + Math.floor(loopCount / 2))` inside `applyGrooveOverrides` where `playback.currentLoopCount` is real — the same pattern the soloist already uses. Cap exported as `motifCapForLoop()` for testability. Loop 0,1 → Standard (1); Loop 2+ → Active (2); never Busy (3+).

**Acceptance:** Loop 0 and Loop 2 produce measurably different motif distributions on the same chart (19/64 steps diverge in Funk with a Busy orchestration entry). Critique test in `tests/standards/drummer-chorus-evolution.test.ts`.
**Effort:** ~3h. **Model:** sonnet (small change, clear test). **Reviewer:** music-theory-reviewer. **Source:** `form-arranger.md` P0 #3, `drums.md` P2 #17.
**Status:** Shipped 2026-05-17. Cap moved from broken seed-time `index` check in `drum-seeder.ts:154-159` (the seeder has no access to `playback.currentLoopCount`; `unrollArrangement` merges same-label iterations so the check was structurally broken — capped every section on every pass) to `applyGrooveOverrides` in `groove-engine.ts` where the per-tick `playback.currentLoopCount` is real. Exported `motifCapForLoop()` for testability. Busy(3) now permanently clipped to Active(2) — intentional per "never Busy (3+)" clause. Mirrors soloist's per-tick `playback.currentLoopCount` pattern (`soloist-pitch-engine.ts:235, 861-877`); establishes template for S6.

### S2. Imperfect Symmetry for bass on repeated sections
Add `sectionOccurrence` to coordination context (already computed in `soloist.ts:128-138`). When `occurrence > 1`, bass adds a deterministic octave displacement on one beat per phrase, seeded by `(sectionId, occurrence, barIndex)`. Same pattern proven on bossa-bass (May 2026 shipped).

**Acceptance:** Verse 1 and Verse 2 of the same chart produce different but deterministic bass lines. Critique test asserts repeat-pass divergence > 10% of notes while staying same pitch-class.
**Effort:** ~4h. **Model:** opus (musical judgment on what variation is right). **Reviewer:** music-theory-reviewer. **Source:** `form-arranger.md` P1 #7.
**Status:** Shipped 2026-05-17. `getSectionContext` / `normalizeLoopStep` extracted from `soloist.ts` into `arranger-utils.ts` as the shared writer for SRDC + the tick-preamble. `sectionOccurrence: 1` published per-tick in `tick-logic.ts` chord-data preamble (defaults match `getSectionContext` no-sectionMap fallback). Bass engine wraps every return path through `withImperfectSymmetry(midi)` in `result()` (`bass-engine.ts:354-444`): at `sectionOccurrence ≥ 2`, on the seeded target beat of each 4-bar phrase, shifts ±12 with hash-seeded direction (not parity — V2/V3/V4 each pick independently per reviewer P1-3). Measured ~44% step-level divergence between V1 and V2, all pitch-class preserving — the shift cascades through `prevMidi` bias into a register migration for the rest of the phrase, which is the intended musical gesture (real bassist commitment to a new register, not a single-note flick). Critique test window 10–70% catches both "gesture removed" and "every-step shifted" regressions; 30/30 reliability. Deferred P2: intensity 0.4 floor suppresses the gesture exactly when subtle variation is most musical (quiet Verse 2). See `tests/standards/bass-imperfect-symmetry-critique.test.ts`.

### S3. Imperfect Symmetry for drums + accompaniment
Mirror S2 for drums (permute one ghost note per 16-step pattern) and accompaniment (rotate one voicing inversion). Same `(sectionId, occurrence, barIndex)` seed.

**Acceptance:** repeat-pass divergence for both engines. Critique tests for each.
**Effort:** ~4h. **Model:** opus (musical judgment per engine). **Reviewer:** music-theory-reviewer. **Source:** `form-arranger.md` P1 #7.
**Status:** Shipped 2026-05-17. Both engines now read `coordination.sectionOccurrence` (wired in S2) per-tick and apply hash-seeded gestures at occurrence ≥ 2. **Drums** (`groove-engine.ts`): permutes exactly one ghost note per 16-step bar per ghost-eligible lane (Snare/HiHat/Open); Kick exempt; foundational steps `[0, 4, 12]` exempt; instrument name folded into the seed so Snare and HiHat permute at different 16ths. Toggle semantics — seeded step that would have fired drops, silent seeded step adds a vel-0.18 ghost. **Accompaniment** (`accompaniment.ts`): from the seeded target bar onward within each 4-bar phrase, the voicing's lowest note is lifted an octave (no-op if it would exceed the chord register slot ceiling of 84). Applied before `compingState.lastVoicingMidis = [...]` so the rotation cascades through `recenterVoicing`/`selectCompactCluster` on subsequent bars — phrase-scoped commitment, matching bass S2's prevMidi-bias cascade. Wired across Country, Neo-Soul, Reggae, Funk, and the STANDARD Jazz/Blues/Rock lane; **power-metal intentionally NOT wired** (a power chord rotated up gives a non-rooted duplicate-octave chord, violating genre identity). Drum divergence calibrated to ~3-25% (per-step independent toggles — theoretical ceiling 6.25%, not bass's 44% prevMidi-cascade), accompaniment cascade gives 1-4 bars/4 divergence. 30/30 reliability on both new critique tests; 76/377 critique suite green; typecheck clean. **Reviewer P2 deferrals (2026-05-17):** (1) accompaniment test fixture's primary seed lands target=0 so the cascade-from-`bar > target` path is not directly observed (compensated by 8-sectionId aggregate in the parity-collapse test); (2) hash-helper consolidation across `bass-engine.ts`/`groove-engine.ts`/`accompaniment.ts` — accomp uses djb2-31-from-0 vs bass/drums' djb2-33-from-5381; independent target-pick distributions across engines are currently a happy hash accident, formalize with deliberate per-engine domain salts when the helper centralizes (tracked alongside deterministic-phrasing S5 TODO); (3) `instHash` for drum lanes uses bare polynomial hash without canonical `scrambleHash` pre-scrambling (empirically fine, future cleanup); (4) `Math.random()` stubbed at 0.5 in both new tests deliberately freezes branching so divergence is attributable to Imperfect Symmetry alone.

**Acceptance:** song-mode playback's final bar is audibly distinct. New `tests/standards/final-bar-cadence.test.ts`.
**Effort:** ~4h. **Model:** opus (musical judgment on each engine's last-bar behavior). **Reviewer:** music-theory-reviewer + state-discipline-reviewer. **Source:** `form-arranger.md` P1 #6.
**Status:** Shipped 2026-05-17. New per-tick flag `coordination.isFinalMeasure` published in `tick-logic.ts` chord-data preamble when `playback.songMode && playback.isEndingPending && stepInForm + stepsPerMeasure >= arranger.totalSteps`; defaulted `false` in `createCoordinationContext` with writer/reader doc-comment. **Drums** (`groove-engine.ts`): Open lane fires Crash (vel 1.25); Kick reinforced (1.3); Snare punctuation (1.15); HiHat fully suppressed across the final bar so the cymbal swell rings out. Imperfect Symmetry ghost-permutation gated off on the final bar (precedence: "land hard, no variation theatre on the way out"). **Bass** (`bass-engine.ts`): final-bar downbeat constructs the note dict directly (bypasses `result()`'s IS wrap and per-style `maxSafeDuration` clamp) — held tonic of `chord.bassMidi ?? chord.rootMidi`, `durationSteps = stepsPerMeasure`, velocity 1.1; sub-beats return null. `isBassActive` force-activates on the final downbeat so per-style gates can't skip the cadence. **Chords** (`accompaniment.ts`): final-bar downbeat builds a chart-driven cadence voicing — pulls only first-octave intervals (≤ 11) from `chord.intervals` so power chord `[0,7]` stays `[0,7]`, dim/halfdim keep their b5, aug keeps #5, sus keeps the suspension, maj7 keeps the 7th, while 9/11/13 extensions drop for the "resolved feel." No invented intervals via `??` fallbacks, no genre-whitelist 7th override; the chart drives the voicing. Anchored to lower chord-slot (MIDI 52-68) for grounded cadence. Velocity factor 0.95 to accent above ordinary comp downbeats. **Reviewer cycle (2026-05-17):** music-theory-reviewer flagged 3 P0s in the initial implementation — `?? 4` / `?? 7` fallbacks invented 3rds and 5ths for power/dim/aug chords, and a static `['Jazz','Blues','Neo-Soul']` whitelist dropped the 7th on Bossa/Funk maj7 charts — plus 5 P1s (bass IS-bypass gap on 2nd+ occurrence outro sections, weak duration thresholds, tautological fixture-pc assertion, velocity comment/code mismatch). See `tests/standards/final-bar-cadence.test.ts`.

### S6. Soloist rhythm engine: density scales with loopCount
Currently only pitch engine reads `loopCount` (device frequency +20%/loop). Rhythm engine has zero loop awareness. Add `densityScale *= 1 + loopCount * 0.15` and `attackJitter += loopCount * 0.05`. Closes the rhythm-side of the Chorus Evolution claim.

**Acceptance:** Loop 0 vs Loop 2 soloist attack count + interval distribution differ measurably. Add to existing soloist critique suite.
**Effort:** ~3h. **Model:** opus (rhythm-engine tuning per the proven phrase-end recipe). **Reviewer:** music-theory-reviewer. **Source:** `soloist.md` P1 #6.
**Status:** Shipped 2026-05-17. `generateRhythmPlan` (`soloist-rhythm-engine.ts`) takes an optional `loopCount` param (clamped `[0,4]` to match the pitch-engine's `liveLoopLift` ceiling at `soloist-pitch-engine.ts:395`). Two knobs: (1) `densityScale *= 1 + loopForRhythm * 0.15` applied on the density branch before it feeds `intensityScale → attackProb baseline` (line 337); (2) `attackProb *= 1 + (Math.random() - 0.5) * 2 * attackJitter` with `attackJitter = loopForRhythm * 0.05` applied as bidirectional jitter at the LAST hop before the `Math.random() <= attackProb` decision (line ~488), AFTER `bypassRhythm` / `isSectionDownbeat` force-1.0 overrides, guarded by `attackProb < 1.0` so cadence anchors can't be jittered below threshold. ### S8. Energy arc calibration: ramp symmetry, per-genre floors, drum-gate alignment
Listening test (2026-05-17) reveals auto-intensity parks below the typical operating range for most genres. Funk in particular spends most of its time at `bandIntensity` ≈ 0.35–0.5, which sits below the `intensity > 0.4` Snare-vs-Sidestick gate at `grooves/funk.ts:195` — so the backbeat reads as Sidestick where a real funk drummer would play full Snare. Three stacking root causes:

1. **Asymmetric downward ramp** (`conductor.ts:183-191`): `multiplier = bandIntensity > targetIntensity ? 2.5 : 1.0` — ramps DOWN 2.5× faster than UP. Excursions above target snap back fast; excursions below linger. The comment says "humans build gradually, drop quickly," but combined with the random jitter at `:445` and `:457` the system has a structural pull toward floor.
2. **Genre floors only exist for Rock/Metal** (`conductor.ts:448-450`). Funk, Neo-Soul, Jazz, Disco, Bossa all lack a floor and spend significant time at section-default energies (0.4-0.5) that are below their natural operating range.
3. **Drum-engine Snare gates were calibrated for a higher baseline than the conductor delivers.** `funk.ts:195` (`intensity > 0.4` for backbeat Snare), `funk.ts:227` (motif-3 needs `> 0.8`), and similar gates across other genres assume a band that lives at 0.5–0.7. The conductor parks at 0.35–0.5.

**Sketch:**
- **Ramp symmetry**: drop the asymmetric multiplier, or invert it (slow descents, fast ascents — "drummers settle in and build"). Pick after a listen-test of both directions.
- **Per-genre floors**: extend the `conductor.ts:448` branch into a small map (suggested starting values for the listen-test: Funk 0.45, Neo-Soul 0.40, Disco 0.45, Jazz 0.30, Bossa 0.30, alongside existing Rock/Metal 0.35). Either add a `floorIntensity` field to each genre's groove config, or centralize in a `genre-energy-floors.ts` map.
- **Drum-gate sweep**: audit all `intensity > 0.4` Snare-vs-Sidestick gates across `grooves/*.ts`; lower to ~0.30–0.35 where the existing 0.4 was a conductor-calibration choice rather than a musical one. Distinguish "Sidestick is genre-correct at low energy" (Bossa, Acoustic ballad) from "Sidestick is a fallback because the conductor under-delivers" (Funk verse).

**Acceptance:**
- At default state (no session timer, no chord chart loaded, default `bandIntensity`), a 32-bar Funk playback emits ≥80% of backbeats on `Snare` rather than `Sidestick`. New `tests/standards/funk-backbeat-presence.test.ts`.
- Conductor-arc test (pair this with S7): default playback reaches `bandIntensity` ≥ 0.5 within the first 16 bars (vs. current ~0.35 baseline).
- 30-run reliability ≥27/30 on each new test.
- Cross-genre regression: Funk, Neo-Soul, Disco, Jazz drummer-critique tests should still pass with updated thresholds; if any tests assumed the prior Sidestick-dominant behavior, update them.

**Effort:** ~6h. **Model:** opus (per-genre floor values + ramp-symmetry direction need musical judgment and a listening check; touches both conductor and drum engines so blast radius is wider than a typical Phase 2 story). **Reviewer:** music-theory-reviewer + state-discipline-reviewer (changes to default `playback.bandIntensity` if pursued cross the state slice). **Source:** Listening-test observation 2026-05-17; adjacent to `form-arranger.md` P1 #4 (section-aware orchestration half-implemented), P2 #15 (conductor "functional but thin").
