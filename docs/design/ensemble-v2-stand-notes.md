## Delivery and boundaries (from the guide's prose sections)

The 2026-09-10 branch-only exception is **retired**. `feat/ensemble-v2-foundation` merged to `main` on 2026-09-12 via PR #1173; start v2 implementations from `main` like any other story, and follow the repository's normal cycle and merge defaults.

**Merging to `main` releases this app (since #1207, 2026-09-15).** Since the cutover (#1357) this app IS `https://ensemble.brndn.zip/`: CI builds it at `/` into the `ensemble-web` image and the `deploy` job releases that tag to prod and then test on every merge, asserting each host's public `/build.json` names the commit. It is gated by the required `v2-checks` context (build + `checks/` Playwright suite) next to `checks` and `e2e-tests`. Nothing of v1 is served or read: `/v1/` and the old beta path `/v2/...` are plain 404s (its redirect and tombstone worker went in #1742). v1's browser data is not read at all (the v1 import was retired in #1736; the `ensemble_*` keys stay on a device, inert), and an old `?s=` link is ignored (#1735). Accounts are on for every device (#1357); the beta's `?accounts=off` opt-out was retired in #1743, and a device's stored `ensemble-v2-preview:accounts` key is left in place, inert. The v1 source, its build and its CI jobs were deleted in #1358; `core/` remains as the engine library this app imports. A chart is one schema, 2; a schema-1 text chart is refused in plain words and never converted (#1740, the Retired text charts row below). The plan that got here is [the rollout](../docs/archive/ensemble-v2-rollout.md), archived.

The trust-boundary bullets as they read before the trim (the guide keeps them without the issue history):

- The account-local database/outbox (`lib/sync/`) is wired to passkey sign-in and the UI
  (#1261 onward). Account code goes in `app/account/` and `lib/account/`; plain `fetch`, and
  `@simplewebauthn/browser` is the only new client dependency.
  `AccountScope` is a local fence, **not authentication**. Production authorization must come
  from a verified server session. Fake transports are contract tests, not cloud support.
- Never migrate/delete guest stores, or the inert keys v1 and the beta left on a device, incidentally. Do not cache private API/auth
  responses or personalized HTML in the anonymous app shell. No credentials or chart contents
  in telemetry. Keep local safety, cloud confirmation and verified offline sounds distinct.
- The band engine (`../band/`, `lib/band-host.ts`) plays; the old generators and the
  worker are gone (#1404). Unsupported chart
  semantics block with an explanation; full iReal compatibility is a target, not today's
  capability.

Its strong preview is timed to match (#1590): the last felt pulse before the ACTIVE SLOT ends, or 600ms where a beat is shorter (`runtime.inLastBeatOfSlot`, the shell's `changeSoon`), and only when that slot ends its chord's run (`endsRun`: the next performed slot is the next different chord — not the same chord again, a hold or an N.C.), so a second chord inside a bar is previewed and a repeated bar is not — never `inLastBeat`/`nextSoon`, which is the chart sheet's per-bar cue; a slot no longer than that notice previews throughout.

### Band sheet and song actions

**The Song menu (#1756)** is a `<Menu>` at the header's ••• (`song-header.tsx`'s `menuButtonRef`, `aria-disabled` while busy so focus can come back to it): Copy link · Duplicate · Export… · More ▸, then Delete… after the divider — five rows, no fields and no help text, the sync facts (`SyncStatus`) above them in `<Menu>`'s `header`. **The song's Key, Mode, Meter and Chord notation are the transport's Key popover's alone (#1757, `app/key-popover.tsx`)**: the Key button ("Key: B♭", `aria-haspopup="dialog"`, `aria-disabled` while busy) opens a `role=dialog` "Key and meter" placed by `useAnchoredPlacement`, a `<Menu>`-style sheet on a phone, dismissed by `useAnchoredDismiss` as `<Menu>` is (Esc, an outside press, Back, Tab past its last field; focus back on the button) and by focus moving elsewhere on the page — never by a blur to null (WebKit blurs to null mid-tap). Closed by the shell instead (a refusal), it lands focus on the selected bar's number, else the Key button (`landFocus`). The Band sheet's Practice tab no longer has Chord notation. Choruses is the chart footer's form-length menu alone.

**Song length (#1784)** is the Practice tab's: Off / 3 / 4 / 5 min, a device preference (`lib/session.ts`'s `songModePreference`, held by the runtime, never a state field or a chart field). On a chart that loops, Play counts the performance (`lib/song-mode.ts`'s `planSong`: the 1–16 choruses whose compiled length lands nearest, ties up) and the band plays that counted copy (`runtime.ts`'s `songPlan`) and stops on its held ending, exactly as a counted chart does; the stand draws the same copy while it plays (`bandChartView`, which is why `useChartView` reads the view again on `playing`), and `currentScore`, Save and the footer stay the document. Planned only on a start from stopped; a tempo change while playing does not re-plan. Disabled with a reason on a chart that counts its own choruses; the readout (`≈3:12 · 4 choruses`) is the shell's `songReadout` memo.

**Export…** (`ExportDialog`) lists Song file, MIDI, Audio (mix), Audio (separate tracks) and, when the song has one, Original source; each closes it once written, and an audio render holds it open with its progress and Cancel until it settles (`dialogRule`'s `busy`: Esc refused, and a close that gets through anyway re-opens it).

**Delete…** is offered for any saved song (`standDeletable`) and routed as the row menu's is (`useSongDeletes`'s `requestDeleteStand`, `app/use-song-deletes.ts`: the `deleted` candidates asked directly, since `standCandidate` is null under a queued Save, then this song's observation read fresh through `watch`): an account song the cloud holds to the cloud delete, one it no longer holds or never confirmed to delete-from-this-device (`purgeConfirmed`, whose step offers Export and, for a song the cloud never confirmed, says this removes the only copy; a song the account turns out to hold stays on the stand with the reason in the error line), a guest song to the guest confirm (`deleteGuestSong`, its Export writing the stand's chart); each takes the song off the stand (`leaveDeletedSong`).

### Dialogs (#1760)

Files, as the row listed them: `app/dialog-close.ts` (`dialogRule`, `closeDialog`), spread onto every `<dialog>`: `app/account/*`, `delete-guest-song.tsx`, `collection-dialogs.tsx`, `song-row-menu.tsx`, `song-menu.tsx`, `export-dialog.tsx`, `import-dialog.tsx`, `guided-form.tsx`, `band-sheet.tsx`; `app/use-modal-dialog.ts` (`useModalDialog`)

One rule set, decided in one place. The shell opens and shuts each of its dialogs through `useModalDialog(open)` (#1894), which owns the ref and the one `showModal()`/`closeDialog` effect; a dialog whose question can go moot (the cloud delete under `inAccount`, the row delete under `rowInAccount`, the sign-out step, the adopt-remote offer) keeps that guard as its own effect beside its comment and hands the hook the derived boolean. `dialogRule({ onClose, busy, keep })`: `busy` means only the dialog's own buttons close it (an action whose answer the dialog shows: a delete, a sign-out, a write, an audio render; or a recovery code on screen, shown once — sign-in's, the recover stage's, the account page's replacement): Esc's `cancel` is refused, and since a browser honours that refusal only with fresh user activation (a repeated Esc, Android's Back), a close that gets through anyway re-opens the dialog at once. A tap on the backdrop closes only a dialog with nothing to lose — never `busy`, never `keep` (typed input not yet saved — Rename, a collection name, an iReal link —, a choice not yet applied — the Repeats and endings guide —, an import under review, the recover stage, the delete-account step, a passkey ceremony). The unmounted import and guide dialogs keep their own Esc, after the spread. Red is for an action that destroys or discards: the deletes, "Sign out anyway" (it discards work this device holds), and "Use the account's version" only when it discards unsaved edits.

**Sign out** is on the account page's Sessions section with its offline reason (`account-page.tsx`); the header's account entry is only the chip ("Signed in", or Finish protecting + Account). Labels are plain words: "Older drafts", "Melody comes back" (the Trade tab's "after N choruses"), and the import dialog is "Import a chart" until a chart is under review, then "Review import". `checks/dialog-rules.spec.ts` walks the dialogs on both projects (the signed-in half on Chromium)

### Bar editing / runtime bridge

Files, as the row listed them: `app/use-bar-drafts.ts` (#1723), `app/use-bar-editing.ts` (the bar and section editing handlers, #1906), the in-bar field in `app/chart-sheet.tsx` (#1723), the phone's docked bar field `app/bar-dock.tsx` (#1724), the bar menu `app/bar-menu.tsx` (+ `app/bar-ruler.ts`, `app/bar-context-fields.tsx`, #1725), the Repeats and endings dialog `app/guided-form.tsx` (+ `app/form-controls.tsx`, its per-bar markers since #1758), the section letter's menu `app/section-menu.tsx` (+ `app/section-settings.tsx`'s fields, #1374, #1726), `lib/form-editing.ts`, `lib/documents.ts` (add/remove bars and sections, section settings), `lib/song-meter.ts` (the song's own meter, #1371, and a section's, #1374 — re-fits only bars whose effective meter changes; blocks, never rounds), `lib/runtime.ts`

The handlers below (`barEditing`, `sectionEditing`, `barMarkers`, `openBarForm`, `applyForm`, the bar and section actions, `changeSongMeter`) live in `useBarEditing`, called after `useDeleteUndo` for its `offerUndo`; they read the render's `current` while `applyScore`/`updateChart` (the shell's) read `currentNow`, and nothing it returns is memoized. Typing on the chart (#1723): in Edit chart a press on a measure chart's bar opens a field in it (`BarEditing`, `useBarEditing`'s `barEditing()`); Tab/Shift-Tab/Enter move bar to bar (passing over bars `editableText` can't print), Esc puts back the bar's applied text. Leaving a bar applies that bar alone (`commitBarDrafts(score, drafts, id)` → `applyScore(score, id)`, which retires only its draft); a bar whose chords don't read stays pending, tinted, and Save (`updateChart`: `commitBarDrafts` over every bar) refuses it, selects it and opens its field, the refusal in the shell's error line. Entering Edit opens no bar (#1726): every bar stays on the page as written until one is pressed. At phone width (`usePhoneWidth`, the 760px breakpoint) the open bar has no field of its own (#1724): the one input is `BarDock`, fixed on top of the on-screen keyboard (its `bottom` from `visualViewport`; it publishes `--bar-dock-space`, the chart's bottom and scroll padding), with ‹ › (`onLeave` ±1, `canMove`), Done (leave, focus to the bar number) and a row of chord-ending keys that insert the ASCII spellings `isScoreChord` reads (`b9`, `#11`; an ending appends when the whole bar is selected, `/` is a spaced hold). A typed lowercase root capitalises itself. While it is up (`data-bar-open` on `.workspace`) the transport row is hidden; it is back after Done.

**The bar menu (#1725)** is the open bar's structure: ⋯ on the bar (top-right) or Ctrl/⌘+. from its field on a laptop, a popover placed beside the bar; ⋯ in the dock on a phone, a sheet over the dock. It holds the beat ruler (`readRuler`/`rulerText`: the bar's chords as spans in HALF counts, holds `/` folded into the chord before; each split a `role=slider`, dragged with captured pointer events or moved by arrow keys a count at a time, Shift for half a count where that is on the step grid; it writes `C Dm` for equal lengths, else `Gm7:3 C7:1`), Key/Mode/Meter/Beat grouping from here (`BarContextFields`), Repeat or ending… (the shell's own `GuidedForm` over every pending bar, unapplied — the menu's ONE repeat path since #1758: the per-bar markers, `FormControls`, for nested and nonstandard forms the guide leaves alone, are the dialog's "Per-bar markers for A · bar N…" view, a live draft change through `barMarkers`; where the pending bars' markers make no form yet, `openBarForm` opens the dialog on them with the guide `blocked`, and "Back to the guide" re-reads the pending bars), Hold last chord, and Insert bar after (`withBarAfter`) / Delete bar (`withoutMeasure`), which commit pending bars first (`updateChart`) and open the resulting bar for typing.

**Calm by default (#1758):** the ruler is the one open group (it is what the menu is for; folded, the most-used control would cost a second tap), every other group is a folded `<details>` with a chevron, and Delete is last after a divider, as in `<Menu>`; the phone's Back to typing (the section menu's Close) sits in the heading row (`.bar-menu-top`) so nothing follows Delete. On a phone both sheets slide up with `menu.css`'s `menu-slide-up` over its `.menu-backdrop` — which here is `pointer-events: none` (`.bar-menu-backdrop`), drawn only, so a press goes through to the bar, dock or letter beneath and the menus' own document outside-press reads it (a press on another bar still opens it).

**Undo after a delete (#1758):** Delete bar and Delete section snapshot the chart and `barDrafts.latest()` BEFORE committing pending bars, and on success `offerUndo` keeps `{ before, drafts, after }` (`DeleteUndo`) in `app/use-delete-undo.ts`'s `useDeleteUndo`, which owns the offer's lifetime while the shell keeps the restore (`undoDelete`, #1896); a `stand-undo` toast (its own always-mounted element in `.stand-stack` (`app/stand-stack.tsx`), so the shell's messages and busy lines cannot push it out) offers Undo for `DELETE_UNDO_MS` (counted per delete, `token`), paused while focused or under a real mouse (`pointerType === 'mouse'`: an iOS tap must not hold it). It is live only while `current === after` and no bar is pending, so any edit, Save (a new revision object) or another song retires it, and an effect clears it so taking the edit back does not revive it. The one exception is a new song's first-change keep (`keptAs`: the same chart at a new revision/`updatedAt`): the offer is carried onto it, `before` taking the kept revision. Undo pressed while another action holds the shell (`run` would turn it away) waits for it (`undoAfterWork`, run when `busy` clears). Where no bar field reopens (a section's Undo), focus goes to the restored section letter or bar number (`undoFocus`), never the page. Undo (`undoDelete`) is `runtime.load(before)` + `draft(before)` + `barDrafts.restore(drafts)`, reopening the deleted bar; its button keeps focus on `mousedown` like the dock's keys, so an open bar's field (and the phone's dock) stays up through the tap. Everything but the bar actions writes the bar's draft through `barDrafts.put`/`draftChange`, so the field and the menu are one draft, applied on leaving the bar. While the menu is open focus is IN it and the field's blur into it is not a leave; Esc (and Back to typing) refocus the field; a press outside closes it — on another bar that bar opens, on this bar or the dock it is typing again, anywhere else it is leaving the bar. The dialog it opens is the field's one ignored blur (`holdForDialog`), so the bar stays open beneath and gets focus back.

**The section letter's menu (#1726)**, in Edit on a measure chart (`SectionEditing`, `useBarEditing`'s `sectionEditing()`), is built the same way — a popover under the letter on a laptop, a sheet on a phone, `role=dialog` "Section X menu": Start here, Name and plays — folded since #1758 — holding Section name and Section plays (`CommitField`: commit on blur or Enter, so a press outside or Esc blurs the focused field first and its typing is kept), Key, mode or meter (`SectionSelects`, folded), Add section after (`withSectionAfter`, its one tonic bar opened for typing) and, after a divider, Delete section (`withoutSection`, with Undo). Each commits pending bars first.

**A leave set off by a press lands only once that press has (`app/after-press.ts`, #1733)**: the field's blur, the bar menu's outside press, and the blur commits of `CommitField` and the tempo field go through `afterPress`, which runs them at the press's click (capture phase, the target already decided) or its end, and before any later key, select choice or press. Applied on the way down, the change re-laid the page out under the pointer (a CI WebKit's status line took a second line and moved Play 22px), so the click missed: Play pressed with a bar open left the bar and never played. Pressed while a bar is open, the letter keeps the field's focus on `mousedown` (a blur there would fold the phone's dock away and move the letter out from under the tap before its click); the menu taking focus then leaves the bar. Outside Edit the letter's menu is still Start here alone. A new song's first change is kept (#1707) only after a pause in presses and keys (`NEW_SONG_KEEP_DELAY_MS`): a bar is left by pressing something else, and a keep begun on that press's way down would hold the one-action lock when its click arrived.

### Shared links (`#chart=`) and retired v1 `?s=` links (#1735)

`?autoplay=1` on it arms playback until the first gesture (#1732: `npm run audition-link` writes `?autoplay=1#chart=…`).

**Old v1 `?s=`/`?prog=` links are not read at all (#1735):** the page opens as the songbook, the parameters are ignored and the URL is left as it is (no code runs on a parameter nobody reads).

### Operator page (#1717)

Its own route at `/admin`, `noindex`, linked from nowhere; read-only over `GET /api/admin/overview` (accounts, storage, and the chart counts by `schemaVersion`, #1731 — `lib/admin.ts` rejects a malformed `charts`), whose allowlist (`ENSEMBLE_ADMIN_ACCOUNT_IDS`, deploy config on the box) is the only gate.

### Offline install / deployment

A newer release installs and waits until the musician presses the songbook footer's Reload (`useOfflineInstall`'s `applyUpdate`, the worker's `skip-waiting` message, #1889) or every tab closes; once it takes over, every tab reloads, except a busy one (playing, unsaved work, a running action), which reloads once it is idle — never a running band's code swapped under it; each worker retires only the older shells under its own cache prefix. `checks/offline-shell.chromium.spec.ts` pins the first two and proves an activating update sweeps only older shells; `checks/foundation-sounds.spec.ts` pins the sound cache's name (it evicts a downloaded file from it by name and expects the app to notice). Both hosts serve the `ensemble-web` image (this export at `/`), released by tag: the CI `deploy` job on every merge, `scripts/deploy-test.sh` for a branch audition on the test host

### Where the app is served from (#1354, #1734)

There is no `ENSEMBLE_V2_BASE`, no `/v2` default and no `withBase`: the dev server, the build, the preview server and the specs all use root paths, and `next.config.mjs` sets no `basePath`. A hand-written `fetch`, `caches` key or `serviceWorker.register` path is simply the root path.
